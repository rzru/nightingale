# Contributing to Nightingale

Thanks for your interest in improving Nightingale! To keep the project focused
and maintainable, contributions follow a **discussion-first** process. Please
read this before opening a pull request.

## Discussion-first workflow

Nightingale is built and maintained by one person. Every feature adds long-term
maintenance cost, so the direction of the app is decided deliberately. **Do not
start writing code for a new feature or change before it has been discussed and
approved.**

The process is:

1. **Start a discussion thread.** Open a thread in
   [GitHub Discussions](https://github.com/rzru/nightingale/discussions)
   describing what you'd like to add or change and why. Include:
   - the problem you're trying to solve or the feature you want,
   - your proposed approach (if you have one),
   - any relevant context (platform, use case, screenshots, logs).

2. **Wait for the discussion to be reviewed.** The maintainer will decide
   whether the change fits the app's scope and direction. This is where we
   figure out *together* whether the feature belongs in Nightingale — not every
   good idea is a good fit for this project, and that's okay.

3. **Wait for the "approved" status.** A discussion is only ready for
   implementation once the maintainer has marked it as **approved**. Only then
   will a corresponding pull request be considered for merging.

> [!IMPORTANT]
> Pull requests that do not link to an **approved** discussion thread will not
> be reviewed or merged, regardless of code quality. This isn't personal — it's
> how we make sure your time isn't spent building something that can't be
> accepted.

## Using AI

AI-assisted work is fine on the **code** side:

- **AI-generated code is welcome.** Use whatever tools help you build.
- **AI-generated PR descriptions are welcome.** As long as they accurately
  describe the change, it doesn't matter how they were written.

There is one hard line, though:

> [!IMPORTANT]
> **I will never engage in a conversation with you if you use AI to talk to me.**
> Discussion threads, issue comments, and any back-and-forth with the maintainer
> must be written by you, in your own words. If a reply reads like it was
> generated by an AI, I will not respond to it. Use AI to write code, not to
> talk to me.

### What doesn't need a discussion first

You can skip straight to a pull request for small, low-risk fixes:

- typos and documentation corrections,
- obvious bug fixes with a clear reproduction,
- minor build/CI fixes.

If in doubt, open a discussion first.

## Submitting a pull request (after approval)

Once your discussion is approved:

1. Fork the repo and create a branch from `master`.
2. Keep the change focused on what was approved in the discussion.
3. Reference the approved discussion thread in the PR description.
4. Make sure the project builds and existing checks pass.
5. Update `CHANGELOG.md` and any relevant docs if your change is user-facing.

## Questions

Not sure whether something is worth proposing? Open a discussion and ask — that's
exactly what it's for.
